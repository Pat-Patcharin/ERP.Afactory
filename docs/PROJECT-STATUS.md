## สิ่งที่ยังไม่ได้ทำ และอยู่นอกงานทั้งสามรอบ

งานสามรอบที่ผ่านมาทั้งหมดอยู่บน**ข้อมูลในหน่วยความจำ** ไม่มีฐานข้อมูล ไม่มี API
ไม่มีการล็อกอินจริง สิ่งเหล่านี้ไม่ใช่ backlog เพราะไม่ใช่งานที่เลื่อนไว้
แต่เป็นชั้นที่ยังไม่เคยเริ่ม

### ฐานข้อมูล

ทุกอย่างเป็น array ใน `data/*.ts` แก้แล้วหายเมื่อ reload
สิ่งที่ต้องตัดสินก่อนเริ่ม

- **Primary key** `product_code` ว่างได้ 51 แถว และมี 5 รหัสซ้ำ (`H-RC005-01`
  ร้ายแรงที่สุด — ผูกกับสินค้าคนละตัว) ต้องเคลียร์ก่อนใส่ unique constraint
- **เลขที่เอกสาร** ตอนนี้ `nextSeq()` นับจาก array ในหน่วยความจำ
  ของจริงต้องเป็น sequence ที่กันชนกันตอนมีผู้ใช้พร้อมกัน
- **สอง code space** ของข้อมูลตัวอย่าง (backlog N-4) ต้องรวมก่อน migrate
  ไม่งั้นจะขน foreign key ที่ชี้ไปที่ไม่มีอยู่จริงเข้าฐานข้อมูล
- **Audit trail** ตระกูลเอกสารขาออกยังไม่มี (backlog ข้อ 4) — ถ้าจะมี
  ควรออกแบบพร้อมกับ schema ไม่ใช่เติมทีหลัง

### นำเข้าข้อมูล

`CLAUDE.md` วางกรอบไว้แล้วเป็น pipeline 6 ขั้น
Source → Map → Normalize → Validate → Preview → Commit แต่ยังไม่ได้เขียน

- ขั้น Validate ใช้ `validateItem()` จาก `pricing.ts` ที่มีอยู่แล้ว
- ตาม pattern เดิม: **import ทุกแถวแล้ว flag error ไม่ drop แถวทิ้ง**
- อ่าน CSV ด้วย SheetJS ต้องใช้ `{ header: 1, raw: false }` ไม่งั้นเลข 0 นำหน้าหาย
- **นี่คือที่ที่ backlog ข้อ 11 ต้องถูกแก้** — รหัสสินค้าหนึ่งชุดข้าม
  product master · price master · เอกสาร ไม่ใช่แก้ที่ mock

### อื่น ๆ ที่ยังไม่เริ่ม

- **ระบบล็อกอินจริง** `DEMO_ACCOUNTS` กับปุ่มสลับบัญชีต้องถูกลบทิ้งทั้งคู่
  มีคอมเมนต์กำกับไว้แล้วในโค้ด
- **ส่งอีเมล** ช่อง Email ใน Notification Settings รอระบบส่งเมลก่อน
- **PDF จริง** (backlog ข้อ 7) ต้องมี backend + file storage
- **Promotion engine** 10 กลไกใน `AFactory_Promotion_Master_v1.xlsx`
  **ยังไม่ได้กำหนด stacking rule — ต้องถามก่อนเขียน**
- **โมดูล Reports** ยังไม่เริ่ม และ**ต้องแก้ backlog N-2 ก่อน**
  ไม่งั้นตัวเลขส่งแล้วกับค้างส่งจะเพี้ยนทั้งคู่

## กฎที่งานสามรอบนี้สอน

อยู่เต็มใน [`BACKLOG.md`](./BACKLOG.md) หัวข้อบนสุด สรุปสั้น ๆ

1. **กฎที่เขียนครบแต่ไม่กัดใคร** เจอซ้ำตลอดสามรอบ — รายการที่ยืนยันแล้วอยู่ใน
   `BACKLOG.md` หัวข้อบนสุด 7 ตัว บวกกับที่กระจายอยู่ในแต่ละข้อ (`noCost` ·
   กฎคู่ค้า Draft · `pickComplete`/`packComplete` ที่ไม่มี guard · ตระกูล `isOverX`)
   เวลาเพิ่มกฎ ต้องมีเทสต์ที่พิสูจน์ว่ามีเคสถูกปฏิเสธจริง **และ**
   ต้องมีข้อมูลที่เดินไปถึงกฎนั้นได้
2. **คอมเมนต์ที่โค้ดไม่ทำตาม** อันตรายกว่าไม่มีคอมเมนต์
3. **งาน refactor: ย้ายของเดิมก่อน ห้ามเขียนใหม่ให้เหมือน** แล้วไล่เทียบทีละบรรทัด
   — "เทสต์เขียว" กับ "ไม่เปลี่ยนพฤติกรรม" ไม่ใช่เรื่องเดียวกัน
4. **เทสต์แนวห้าม ต้องฉีดของผิดเข้าไปดูว่าแดงจริงก่อนเชื่อ**
5. **ข้อ backlog ที่พิสูจน์ด้วยโค้ดได้ ให้เขียนเทสต์ที่แดงเมื่อมันถูกแก้**
   เพื่อให้ backlog เตือนตัวเองตอนหมดความจำเป็น
6. **อย่าเขียนตัวเลขจากความจำ** ใช้กับ contrast ratio เท่ากับที่ใช้กับโค้ด
7. **เจอของที่ทำเรื่องนั้นอยู่แล้ว ให้หยุดถามก่อนสร้างใหม่** — กฎนี้กันงานซ้ำ
   ไปได้ทั้งรอบหนึ่งครั้ง
